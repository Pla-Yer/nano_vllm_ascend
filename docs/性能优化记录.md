> 模型：Qwen3-0.6B · 设备：Ascend 910B3 · dtype：bf16
>
> 每轮优化包含 layer 微基准（`bench_layers.py`）和端到端基准（`bench_e2e.py`），以验证单项优化的实际收益。

## P1 RMSNorm：手写 → `npu_rms_norm`

将手写的分解算子（转 fp32 → 平方 → mean → rsqrt → 乘 weight → cast 回原 dtype）替换为单个 `npu_rms_norm` 算子。

### Layer 基准

```powershell
python examples/bench_layers.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --tokens 1,16,128,512 --warmup-iters 20 --iters 200 \
  --output-json bench_outputs/layers_p1_rmsnorm.json
```

| Layer | P0 (ms) | P1 (ms) | 加速 |
|-------|---------|---------|------|
| rms_norm_hidden [1,1024] | 0.1683 | 0.0546 | **3.08×** |
| rms_norm_head [1,16,128] | 0.1654 | 0.0548 | **3.02×** |
| rms_norm_hidden [512,1024] | 0.1641 | 0.0588 | **2.79×** |
| rms_norm_head [512,16,128] | 0.1642 | 0.0586 | **2.80×** |

### 端到端基准

```powershell
python examples/bench_e2e.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --batch-size 1 --max-new-tokens 128 --iters 5 \
  --output-json bench_outputs/e2e_p1_rmsnorm.json
```

| 指标 | P0 | P1 | 变化 |
|------|----|----|------|
| prefill_s | 0.0550 | 0.0414 | **-24.7%** |
| decode_s | 6.7034 | 5.0547 | **-24.6%** |
| total_s | 6.7584 | 5.0961 | **-24.6%** |
| prefill_tok/s | 563.75 | 748.88 | **+32.8%** |
| decode_tok/s | 18.95 | 25.14 | **+32.7%** |
| total_tok/s | 23.53 | 31.22 | **+32.7%** |

### 分析

- 单次 forward 有 4 次 norm（input_layernorm、q_norm、k_norm、post_attention_layernorm），28 层共 112 次/token。
- 每次 norm 节省约 0.11 ms，累计减少约 12 ms/token。
- decode 从约 53 ms/token 降至约 39 ms/token。

## P2 RoPE：预计算 cos/sin + `npu_rotary_mul`

两项优化：
1. cos/sin 从"每次 forward 现算"改为初始化时预计算缓存（之前只缓存 inv_freq）。
2. apply 从多个 PyTorch 小算子（cos.to、sin.to、unsqueeze、rotate_half、cat、mul/add）替换为 `torch_npu.npu_rotary_mul`。

### Layer 基准

```powershell
python examples/bench_layers.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --tokens 1,16,128,512 --warmup-iters 20 --iters 200 \
  --output-json bench_outputs/layers_p2_rope.json
```

| Layer | P1 (ms) | P2 (ms) | 变化 |
|-------|---------|---------|------|
| rope_full [1,16,128] | 0.5200 | 0.3241 | **-37.7%** |
| rope_full [16,16,128] | 0.5282 | 0.3243 | **-38.6%** |
| rope_full [128,16,128] | 0.5291 | 0.3273 | **-38.1%** |
| rope_full [512,16,128] | 0.5287 | 0.3266 | **-38.2%** |

### 端到端基准

```powershell
python examples/bench_e2e.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --batch-size 1 --max-new-tokens 128 --iters 5 \
  --output-json bench_outputs/e2e_p2_rope.json
```

| 指标 | P1 | P2 | 变化 |
|------|----|----|------|
| prefill_s | 0.0414 | 0.0364 | **-12.1%** |
| decode_s | 5.0547 | 4.3901 | **-13.1%** |
| total_s | 5.0961 | 4.4265 | **-13.1%** |
| prefill_tok/s | 748.88 | 852.12 | **+13.8%** |
| decode_tok/s | 25.14 | 28.93 | **+15.1%** |
| total_tok/s | 31.22 | 35.92 | **+15.1%** |

### 分析

- RoPE 单层约 -38%，但 RoPE 在整体 decode 中占比不如 RMSNorm 大，端到端收益约 13-15%。
- P0 → P2 累计：decode_tok/s 从 18.95 提升至 28.93，**总提升约 +52.7%**。

## P3 MLP：融合 gate/up/down proj

将 `down_proj(silu(gate_proj(x)) * up_proj(x))` 的手写流程尝试融合为更少的算子调用。

### Layer 基准

| Layer | P2 (ms) | P3 (ms) | 变化 |
|-------|---------|---------|------|
| mlp [1,1024] | 0.1684 | 0.1383 | -17.9% |
| mlp [16,1024] | 0.1762 | 0.1480 | -16.0% |
| mlp [128,1024] | 0.1772 | 0.1474 | -16.8% |
| mlp [512,1024] | 0.1766 | 0.1478 | -16.3% |

### 端到端基准

```powershell
python examples/bench_e2e.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --batch-size 1 --max-new-tokens 128 --iters 5 \
  --output-json bench_outputs/e2e_p3_mlp.json
```

| 指标 | P2 | P3 | 变化 |
|------|----|----|------|
| decode_s | 4.3901 | 4.4120 | +0.5% |
| decode_tok/s | 28.93 | 28.79 | -0.5% |
| total_tok/s | 35.92 | 35.75 | -0.5% |

### 分析

- Layer 级 MLP 有约 16-18% 下降，但端到端 decode tok/s **没有提升，反而微降 <1%**。
- 说明在 decode 小 batch（T=1）场景下 MLP 不是瓶颈，收益被调度开销掩盖。
- **结论：暂时保留原实现，MLP 融合搁置。**

## P4 ACL Graph

使用 ACL Graph 捕获 decode 过程，消除逐 kernel 调度开销。

### 端到端基准 — batch_size=1

```powershell
python examples/bench_e2e.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --batch-size 1 --max-new-tokens 128 --iters 5 --enable-decode-graph \
  --output-json bench_outputs/e2e_p4_graph.json
```

| 指标 | P2 (无 Graph) | P4 (Graph b=1) | 变化 |
|------|--------------|----------------|------|
| decode_s | 4.3901 | 1.2603 | **-71.3%** |
| decode_tok/s | 28.93 | 100.79 | **+248.4%** |
| total_tok/s | 35.92 | 122.38 | **+240.7%** |
| HBM peak | 47.24 GB | 49.54 GB | +2.3 GB |

Graph stats：captures=1, replays=762, fallbacks=0

### 端到端基准 — batch_size=4

```powershell
python examples/bench_e2e.py \
  --model-path /home/player/models/Qwen3/Qwen/Qwen3-0___6B/ \
  --batch-size 4 --max-new-tokens 128 --iters 5 --enable-decode-graph \
  --output-json bench_outputs/e2e_p4_graph_b4.json
```

| 指标 | P4 (Graph b=1) | P4 (Graph b=4) | 变化 |
|------|----------------|----------------|------|
| decode_tok/s | 100.79 | 372.42 | **+269.5%** |
| total_tok/s | 122.38 | 453.09 | **+270.3%** |
| prefill_tok/s | 789.58 | 3128.76 | **+296.3%** |

### 分析

- ACL Graph 消除了逐 kernel 调度开销，decode 性能提升巨大。
- b=1 时 decode_tok/s 从 28.93 → 100.79（**3.48× 加速**）。
- b=4 时 decode_tok/s 达 372.42，总吞吐 453 tok/s。
- 代价：额外约 2.3 GB HBM 用于 graph 捕获。

## 总览

| 阶段 | 优化内容 | decode_tok/s | 累计加速 | 关键改动 |
|------|----------|-------------|---------|----------|
| P0 | Baseline | 18.95 | 1.00× | — |
| P1 | RMSNorm → npu_rms_norm | 25.14 | 1.33× | 112 次/step norm 算子合并 |
| P2 | RoPE → npu_rotary_mul | 28.93 | 1.53× | cos/sin 预计算 + 融合 apply |
| P3 | MLP 融合（搁置） | 28.79 | 1.52× | 非瓶颈，无实际收益 |
| P4 | ACL Graph (b=1) | 100.79 | **5.32×** | 消除 kernel 调度开销 |
| P4 | ACL Graph (b=4) | 372.42 | **19.65×** | 批量 graph replay |
